# Расширенное руководство по рабочему процессу 1cenc

Документ описывает особенности формата Blu-ray, функции и примеры расширенного процесса кодирования. В отличие от базового руководства, здесь показаны не все шаги.

**Как сообщить о проблеме**
- Проблемы можно отправлять через [GitHub Issues](https://github.com/iAvoe/OneColumnEncoder/issues) или [комментарии NazoRip](https://nazorip.site/archives/1593/). Перед сообщением убедитесь, что причина связана с 1cenc, и приложите скриншоты, логи выполнения и ffprobe.

## Форк (Fork)

Форк клонирует полное текущее состояние программы и создаёт два одинаковых экземпляра без явного главного и подчинённого. Такая идея известна по Git, VMFork и некоторым сетевым играм PVE.

**Экземпляр (Instance)**
- Конкретная реализация, созданная на основе модели или схемы. Экземпляры одной модели имеют общую структуру данных, но хранят независимые значения. —Wikipedia

<img src="./img2-all/1-Fork-Usage.png" alt="Функция Fork" width=800 />

> Удобство Fork заключается в устранении повторного запуска и повторной настройки.
> Запущенные экземпляры можно различать по PID (идентификатору процесса) на панели задач или в заголовке программы.

### Fork — Основной процесс
1. **Завершите общую настройку**
   * Выберите программу верхнего уровня (фильтрация) и программу нижнего уровня (кодировщик)
   * Импортируйте исходное видео
   * При необходимости задайте общие параметры видеофильтров и кодирования
2. **Создайте необходимое количество экземпляров для требуемых вариантов**
   * 2: Сжатие без потерь | Сжатие с потерями
   * 2: Вшитые субтитры | Встроенные субтитры
   * 4: x264-1080p | x264-720p | x265-1080p | x265-720p
   * N: Попробуйте разные значения параметров кодирования, чтобы найти лучший результат, или просто используйте их для тестирования
3. **Разделите настройки каждого экземпляра**
   * Отдельные видеофильтры, параметры кодирования и т. д.
   * Output Settings (Path and Filename): задайте разные имена выходных файлов

### Fork — Распределение по NUMA-узлам (необязательно)
1. **Завершите общую настройку**
   * Выберите программу верхнего уровня (фильтрация) и программу нижнего уровня (кодировщик)
   * Импортируйте источники в Queue Mode или Repart Mode (описано ниже)
   * При необходимости задайте общие параметры видеофильтров и кодирования
2. **Создайте по одному экземпляру для каждого доступного NUMA-узла**
3. **Разделите рабочую нагрузку между экземплярами**
   * Выборочно удалите дублирующиеся задачи, чтобы равномерно распределить работу между N узлами
     * Queue Mode → Откройте Queue Editor → Кнопка Delete
     * Repart Mode → Откройте Repart Editor → Найдите Output Queue → Нажмите Delete
     * «Сортировка по размеру файла» может дополнительно улучшить распределение
   * Parallelism Control: назначьте каждый экземпляр отдельному вычислительному узлу

> Queue Mode и Repart Mode не позволяют вручную задавать имена файлов, но удаление дубликатов предотвращает перезапись.
> Это создает эффект, аналогичный планированию на основе пула потоков в x265, но применительно к x264...

### Другие применения Fork
**Проверка во время кодирования:** главное окно скрывается, поэтому другой экземпляр позволяет просматривать настройки.

**Плотное планирование:** ограничьте экземпляры 1–4 ядрами или одним CCD AMD ZEN. Задачи станут медленнее, но возрастёт эффективность кэша и пакетной обработки; видео высокого разрешения может потребовать слишком много памяти.

## Формат Blu-ray

**Внимание:** содержимое диска может происходить из незаконного источника. Перед работой изучите местные и международные нормы авторского права и правила законности самого содержимого.

### Структура файлов и выбор режима кодирования
Этот раздел предназначен для тех, кто впервые работает с Blu-ray, поэтому содержит подробности, предположения и выводы. Структура ниже получена с помощью `Get-PSTree`.

**Основная структура:**
```
BDMV/
├─ index.bdmv        [вход] индекс заголовков/навигация
├─ MovieObject.bdmv  [навигация] команды/управление воспроизведением
├─ PLAYLIST/         [список воспроизведения] *.mpls, порядок воспроизведения
├─ CLIPINF/          [данные клипов] *.clpi, соответствуют номерам m2ts
├─ STREAM/           [потоки] *.m2ts ★ тип содержимого можно оценить по размеру
├─ META/DL/          [метаданные/товарный знак] .xml/.jpg
├─ BACKUP/           [резервная копия] дубликаты ключевых файлов, можно пропустить
└─ CERTIFICATE/      [сертификат] id.bdmv, можно пропустить
```

## Списки воспроизведения Blu-ray

Как показывают примеры выше, определять тип источника только по структуре и размеру файлов утомительно и чревато ошибками. Поэтому лучше сменить подход — разбирать списки воспроизведения, воспроизводя опыт просмотра Blu-ray-плеера.

1cenc через ChapterTools Core читает папку PLAYLIST в структуре Blu-ray, показывает все обобщённые списки воспроизведения и подсписки и позволяет строить очередь кодирования или очередь репартиции, выбирая нужные списки.

### PLAYLIST (.mpls)

Файлы списков воспроизведения. Один файл `.mpls` обычно задаёт один Playlist, который через PlayItem ссылается на конкретные потоки `.m2ts` и задаёт сочетание используемых видео, аудио и субтитров.

По способу организации Playlist и назначению распространённые структуры можно свести к следующим:

#### Одно видео, много субтитров

Несколько Playlist указывают на **одно и то же видео**, но выбирают разные сочетания субтитров/аудиодорожек
* **Один файл — несколько списков**: один `.mpls` содержит несколько Playlist с разными субтитрами
* **Несколько файлов — по одному списку**: несколько `.mpls` содержат по одному Playlist, указывающему на один и тот же видеоклип с разными субтитрами
* **Признаки**:
  * Длительность воспроизведения Playlist почти одинакова
  * Ссылки на файлы `.m2ts` сильно пересекаются
  * Основные различия обычно в выборе субтитров, аудио и других потоков

#### Основной материал и бонусы

Разные Playlist соответствуют независимому содержимому: фильму, телу концерта, бонусам, закадровым материалам и т.д.

* **Один файл — несколько списков**: один `.mpls` содержит несколько Playlist, указывающих на разное содержимое
* **Несколько файлов — по одному списку**: каждый `.mpls` соответствует одной единице содержимого
* **Признаки**:
  * Основной материал обычно имеет **наибольшую длительность воспроизведения**
  * У фильмов и концертов Playlist обычно немного, а число Clip, на которые ссылается один Playlist, относительно сосредоточено
  * У сериалов обычно есть несколько Playlist близкой длительности
  * Номера Playlist/Clip у сериалов часто следуют непрерывной или периодической закономерности
  * Один Playlist может ссылаться более чем на 4 Clip, составляя целый эпизод

#### Реклама, MV и короткие материалы
Реклама, музыкальные клипы (MV), трейлеры, короткие бонусы и другое короткое содержимое.

* **Обычный случай**: один `.mpls` соответствует одному основному Playlist
* **Признаки**:
  * Длительность воспроизведения заметно короче, чем у основного материала
  * Обычно ссылается лишь на несколько Clip `.m2ts`
  * Номера Playlist/Clip иногда показывают слабую последовательную или групповую закономерность
  * На аниме-BD могут также выступать отдельными короткими материалами: OP, ED, PV, CM и т.д.

> Вышесказанное — чисто эмпирическая оценка (грубо говоря, обоснованные догадки), а не стандарт классификации.

### Queue Mode

Инструмент быстрого импорта основного материала из структуры Blu-ray-диска в режимах Queue Mode и Repart Mode.

1. Нажмите «Queue Mode» в главном окне 1cenc.
2. В диалоге «Импортировать Blu-ray?» выберите «Подтвердить».
   <img src="./img2-all/2-Queue-Mode-Import-Branch.png" alt="Ветка импорта Queue Mode" width=500 />
3. Выберите папку `PLAYLIST` внутри папки Blu-ray (`BDMV`) и подтвердите — появится селектор списков Blu-ray.
   <img src="./img2-all/3-BDPlaylistSelector.png" alt="Выбор списка Blu-ray 1" width=700 />
4. В первой колонке определите кластер (Cluster) с потоком основного материала.

5. Во второй колонке выберите Playlist основного материала и нажмите кнопку добавления внизу колонки.

### Repart Mode
1. Нажмите «Repart Mode» в главном окне 1cenc.
2. В диалоге «Импортировать Blu-ray?» выберите «Подтвердить».
3. Выберите итоговый список (Final Playlist) и подтвердите.
   <img src="./img2-all/6-BDPlaylistSelector-3.png" alt="Выбор списка Blu-ray 4" width=500 />

На этот раз видно дополнительное предупреждение: *исходное видео помечено как чересстрочное.* — перед обработкой может потребоваться преобразование.

#### Чересстрочное видео Blu-ray

По историческим причинам исходный стандарт Blu-ray ограниченно поддерживает 1080p:
- 1080p @ 23.976 / 24 fps (прогрессивная развёртка, фильмы)
- 1080i @ 29.97 / 25 fps (чересстрочная, т.е. 59.94i / 50i, телевидение)
- 1080p @ 59.94 / 50 fps (BD-ROM не поддерживает; относится к спецификации Ultra HD 4K Blu-ray)

В результате большинство Blu-ray-плееров отвергают прогрессивные источники 30fps. Отсюда возникли две стратегии совместимости:
1. Сигнализировать чересстрочную схему декодирования через SPS/PPS, реализуя псевдо-29.97fps
    - На деле это прогрессивная развёртка, что видно сразу при воспроизведении
    - Можно перекодировать без потерь, но некоторые «упрямые плееры», по слухам, принудительно применяют лишний деинтерлейсинг с потерей качества
2. Кодировать как чересстрочное, возможно с Pulldown 3:2 или другого формата, реализуя формат 1080i 29.97
    - Требуется покадровый просмотр для выявления закономерности Pulldown и выбора правильного набора восстанавливающих фильтров

> Возможности 1cenc по восстановлению Pulldown ограничены, поэтому пока нужна традиционная ручная обработка; она требует длинного описания и здесь опущена
> Стратегий совместимости может быть больше двух

**Результат проверки воспроизведением:** источник на рисунке — псевдочересстрочное видео (случай 1), можно нажимать подтверждение и продолжать.

#### Редактор Repart

Служит для переразбиения N входных видео на M выходных (виртуальное соединение + разделение). Механизм придуман не в 1cenc, а заимствован из [Haruite/BluraySubtitle](https://github.com/Haruite/BluraySubtitle) — мощного полностью автоматического проекта BDRip для Blu-ray.

**Виртуальное соединение:** предполагается, что все источники уже соединены в один длинный поток; команды кодирования «соединение—разделение» создаются только на этапе генерации итоговых команд

<img src="./img2-all/7-RepartConfModal.png" alt="Редактор Repart" width=650 />

- Сверху: виртуальная общая временная шкала, полученная соединением входных источников слева снизу по порядку
  - Вертикальные линии: разделители, образующие итоговую очередь видео
- В центре: инструменты редактирования разделителей для добавления, перемещения, удаления и точной настройки позиций
- Снизу: список очереди вывода, обновляющийся при изменении разделителей; если разделители не двигать, порядок можно менять вручную
- Справа: многокадровый предпросмотр для проверки позиций разделителей, отрисовывается при выборе любого разделителя

**Основные операции**
- **Импорт списка Blu-ray:** данные глав преобразуются в разделители — оставляйте или удаляйте их в зависимости от того, нужно ли разделение
- **Обычный импорт:** введите метку времени каждого реального разреза в редактор разделителей и нажмите «Добавить» (или дважды щёлкните примерную позицию на шкале, а затем уточните)
- Дважды щёлкните пустое место шкалы, чтобы добавить новый разделитель
- Перетаскивайте разделители для примерного перемещения, но пересекать соседние разделители нельзя

**Решение о сохранении разделителей**
На примере концертного источника выше:
- Предпросмотр → свет в зале гаснет в момент разделителя — предположительно разбиение по песням
  - Подтвердите предположение проверкой воспроизведением, затем делите по потребности в эпизодах
- Некоторые разделители стоят очень близко → проверка предпросмотром → чёрный экран — предположительно короткие перерывы и подготовка сцены
  - Оставьте разделители, чтобы исключить эти отрезки из списка вывода
